# Замер: Чтение с реплик

## Параметры теста

| Параметр        | Значение                             |
| --------------- | ------------------------------------ |
| Тест            | replica-only                         |
| Threads         | 50                                   |
| Ramp-up         | 10s                                  |
| Duration        | 60s                                  |
| DB_REPLICA_PORT | 5433 (реплики)                       |
| Эндпоинты       | GET /user/get/{id}, GET /user/search |
| Think Time      | 100ms                                |
| Тестовых данных | 10000                                |

| Throughput     | 140.3 req/s |

| Min Latency    | 0 ms        |
| Max Latency    | 1953 ms     |
| Errors         | 0 (0.00%)   |
| Всего запросов | 8564        |

## Сравнение мастер vs реплики

| Метрика     | Мастер      | Реплики     | Разница |
| ----------- | ----------- | ----------- | ------- |
| Throughput  | 161.5 req/s | 140.3 req/s | -13%    |
| Avg Latency | 463 ms      | 546 ms      | +18%    |
| Max Latency | 1611 ms     | 1953 ms     | +21%    |
| Errors      | 0 (0.00%)   | 0 (0.00%)   | —       |

Реплики показали чуть более высокую latency возможно из-за overhead HAProxy-балансировки между двумя нодами.

## Конфигурация кластера

- Patroni: 1 мастер + 2 реплики (async)
- HAProxy: порт 5432 (RW → primary), порт 5433 (RO → replicas)
- Чтение направлено на реплики (DB_REPLICA_PORT=5433)
- HAProxy балансирует между patroni-2 и patroni-3
